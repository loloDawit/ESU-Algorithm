# Web engine

A TypeScript port of the ESU engine, for an in-browser version of the
visualizer. No UI yet: this is the algorithm, the session, and the tree
layout, with the tests that prove they behave like the desktop app.

```bash
npm install
npm test          # 58 tests
npm run typecheck
```

## How the port is kept honest

`test/java-golden.json` is **generated by the Java implementation**: for each
sample graph and subgraph size, it records which node every single step builds,
how many subgraphs are found, and exactly which ones. `equivalence.test.ts`
requires this port to reproduce all of it.

The per-step trace is the important part. Totals alone do not pin the
traversal — reversing the order candidates are taken in gives the same number
of steps and the same answers by a different route, and an earlier version of
this test passed with exactly that mutation in place. The visualizer shows the
search one step at a time, so the route is observable behaviour, not an
implementation detail.

`oracle.test.ts` additionally carries over the brute-force check from the Java
suite: enumerate every subset of the right size, keep the connected ones, and
require ESU to return exactly that set with no duplicates.

## Regenerating the fixtures

They only need regenerating if the Java engine's behaviour changes on purpose.
The generator lives in the commit that added this directory.
